1. 量子糾錯研究流程與 el-loom 的角色

1.1 典型 QEC 研究問題

博士階段與進階研究者在 QEC 領域常見的研究問題包括：

  • 為特定硬體限制（耦合圖、退相干機制、量測頻率）設計新的穩定子碼。
  • 針對已知碼（如 surface code, color code）在非對稱噪聲或具體硬體噪聲下重新評估閾值。
  • 研究新型解碼器（neural decoder, tensor-network decoder, belief propagation, etc.）的效能。
  • 設計自訂的量測排程、閘排程（schedule），分析捨入誤差與時間相關噪聲的影響。
  • 比較不同碼族（code families）在漸近尺度（asymptotic scaling）上的邏輯錯誤率表現。

這些問題的共同需求是：能快速、系統性地把「抽象的碼結構＋噪聲模型」轉成「可重現的數值實驗」。el-loom 正是為此設計的一套 Python 工具，重點在於：

  • 對穩定子碼與量測主體（measurement circuits）的統一抽象。
  • 與 stim 等高效模擬器整合，進行大規模蒙地卡羅模擬。
  • 支援多種解碼器與輸出格式，便於後續資料分析。

2. 從數學形式到 el-loom 資料結構：自訂穩定子碼

2.1 一般穩定子碼的數學定義

一個 穩定子碼 定義在 \(n\) 個物理量子比特上，其穩定子群 \(S\) 為 \(n\)-粒子 Pauli 群中的一個阿貝爾子群，且不包含 \(-I\)。令 \(S = \langle S_1,\dots,S_{n-k} \rangle\)，則其編碼空間為 \[ \mathcal{C} = \{ \lvert \psi \rangle \in (\mathbb{C}^2)^{\otimes n} : S_i \lvert \psi \rangle = \lvert \psi \rangle,\, \forall i \} . \] 若 \(S\) 的生成元線性獨立（在 Pauli 群上 modulo \(\pm 1\)），則編碼 \(k = n - \text{rank}(S)\) 個邏輯比特。

邏輯 Pauli 生成元可選取為 \[ \{ \overline{X}_1,\dots,\overline{X}_k,\overline{Z}_1,\dots,\overline{Z}_k \} \] 使得：

  • \([ \overline{X}_i, \overline{Z}_j ] = 0\) 對 \(i \neq j\)，
  • \(\{ \overline{X}_i, \overline{Z}_i \} = 0\)（反對易），
  • 對所有 \(i,j\)，\([\overline{X}_i, S_j] = [\overline{Z}_i, S_j] = 0\)。

2.2 Pauli 向量表示與二元矩陣形式

在實作時，我們常使用 binary symplectic representation 來表示 Pauli： \[ P = i^\kappa X^{\mathbf{a}} Z^{\mathbf{b}} \quad \leftrightarrow \quad (\mathbf{a} \mid \mathbf{b}) \in \mathbb{F}_2^{2n}, \] 其中 \(\mathbf{a},\mathbf{b} \in \mathbb{F}_2^n\)；第 \(j\) 比特若為 \(X\) 則 \(a_j=1,b_j=0\)，若為 \(Z\) 則 \(a_j=0,b_j=1\)，若為 \(Y\) 則 \(a_j=b_j=1\)，若為 \(I\) 則 \(a_j=b_j=0\)。

兩個 Pauli \(P,Q\) 的（反）對易性由辛內積決定： \[ P Q = (-1)^{\langle P,Q\rangle} Q P, \] 其中 \[ \langle (\mathbf{a}\mid\mathbf{b}), (\mathbf{c}\mid\mathbf{d}) \rangle = \mathbf{a}\cdot\mathbf{d} + \mathbf{b}\cdot\mathbf{c} \in \mathbb{F}_2. \]

因此，一個穩定子碼可由一個 \((n-k) \times 2n\) 的二元矩陣 \[ H_S = [A\mid B] \] 來表示，其中每一列對應一個穩定子生成元的 Pauli 向量表示。

2.3 在 el-loom 建立自訂碼的核心概念

在 el-loom 中，核心抽象並非只是一個靜態的 \(H_S\)，而是：

  1. 幾何／拓樸資料： qubit 位置、鄰接關係、層級結構（如 lattice, tiling）。
  2. 穩定子、邏輯算符的 Pauli 結構： 可視為 algebraic layer。
  3. 測量電路與 schedule： 如何在時間上實現這些穩定子的量測。

具體到 Python，典型流程（以 pseudo-code 表示）如下： 


from loom import codes, circuits, layouts

# 1. 定義 qubit layout (可 1D, 2D, graph-based)
layout = layouts.CustomLayout(qubits=range(n), connectivity=edges)

# 2. 定義 stabilizer 與 logical Pauli
stabilizers = [
    "X0 X1 X3 X4",  # textual Pauli representation
    "Z1 Z2 Z4 Z5",
    # ...
]
logical_x = ["X0 X2 X4", ...]
logical_z = ["Z1 Z3 Z5", ...]

code = codes.StabilizerCode(
    n_qubits=n,
    stabilizers=stabilizers,
    logical_x=logical_x,
    logical_z=logical_z,
    layout=layout,
)

# 3. 從 code 構造 syndrome measurement circuit
meas_circuit = circuits.SyndromeMeasurementCircuit.from_code(code)

實際 API 名稱請以官方文件為準，上述示例只展示「抽象層級」。核心思想是：

  • 你應該把自訂碼的數學規格（穩定子、邏輯算符）明確寫入。
  • 幾何（layout）是為了實現局域性約束與 schedule 建構。
  • 電路（circuit）是為了後續噪聲插入與模擬。

3. 從數學設計到具體範例：自訂小型 topological code

3.1 範例：一個 9-qubit planar surface code (小型)

為了示範，我們考慮一個簡化的 9-qubit planar surface code patch。物理 qubit 排列成 \(3\times3\) 方格： 

q0  q1  q2
q3  q4  q5
q6  q7  q8

對於此簡化示例，設計 4 個 \(Z\)-type plaquette 穩定子與 4 個 \(X\)-type star 穩定子（為了示範，這裡採一個稍不標準但結構清楚的版本）。

  • \(Z\)-type 穩定子（作用在 plaquettes 上）： \[ S^{(Z)}_1 = Z_0 Z_1 Z_3 Z_4,\quad S^{(Z)}_2 = Z_1 Z_2 Z_4 Z_5, \] \[ S^{(Z)}_3 = Z_3 Z_4 Z_6 Z_7,\quad S^{(Z)}_4 = Z_4 Z_5 Z_7 Z_8. \]
  • \(X\)-type 穩定子（作用在頂點 star）： \[ S^{(X)}_1 = X_0 X_1 X_3 X_4,\quad S^{(X)}_2 = X_1 X_2 X_4 X_5, \] \[ S^{(X)}_3 = X_3 X_4 X_6 X_7,\quad S^{(X)}_4 = X_4 X_5 X_7 X_8. \]

顯然，各 \(Z\)-type 彼此對易，各 \(X\)-type 彼此對易，而任意一個 \(X\)-type 與任意一個 \(Z\)-type 的重疊 qubit 數為偶數（0,2,4），故亦對易。總共有 8 個獨立生成元，但其中一個整體相乘關係可能導致 rank < 8；假設最後 rank 為 8，則 \[ k = n - \text{rank}(S) = 9 - 8 = 1, \] 是一個 \([[9,1,d]]\) code。最小距離 \(d\) 約為 3（對應穿越 patch 的 string-like 邏輯算符）。

3.2 binary symplectic 檢查與距離估計

將上述 8 個穩定子轉成 Pauli 向量表示，建立 \(H_S\)： \[ H_S = \begin{bmatrix} \mathbf{a}^{(X)}_1 & \mathbf{b}^{(X)}_1\\ \vdots & \vdots\\ \mathbf{a}^{(X)}_4 & \mathbf{b}^{(X)}_4\\ \mathbf{a}^{(Z)}_1 & \mathbf{b}^{(Z)}_1\\ \vdots & \vdots\\ \mathbf{a}^{(Z)}_4 & \mathbf{b}^{(Z)}_4 \end{bmatrix} \in \mathbb{F}_2^{8\times 18}. \]

對於任意候選邏輯 Pauli \(L = (\mathbf{a}_L\mid\mathbf{b}_L)\)，它需滿足：

  1. \(L\) 與所有穩定子對易： \[ H_S \, J \, L^\top = \mathbf{0} \quad\text{(mod 2)}, \] 其中 \[ J = \begin{bmatrix} 0 & I_n\\ I_n & 0 \end{bmatrix} \in \mathbb{F}_2^{2n\times 2n}. \]
  2. \(L\) 不屬於穩定子群（modulo 相位），即 \(L \notin \text{row-span}(H_S)\)。

距離 \(d\) 則是所有 非穩定子 邏輯 Pauli 中最小的 Pauli weight： \[ d = \min_{L \in N(S)\setminus S} \mathrm{wt}(L), \] 其中 \(N(S)\) 為 normalizer。

在實作上，可利用高效 binary linear algebra（numpy 或 rust 實作）搜尋所有重量 \(\le d_{\max}\) 的 Pauli，檢查是否屬於 normalizer \& 非穩定子。el-loom 通常會提供類似：

  • 給定 StabilizerCode 結構，自動計算 \(k\)、距離估計等。
  • 或與外部 library（如 qecsim, stim）互通。

  • 輸出對應的測量電路骨架（skeleton），再疊加噪聲模型。

4. 噪聲模型與時間結構的嚴謹建模

4.1 噪聲通道的抽象與 local noise 假設

在 QEC 理論分析中，我們通常假設 局域獨立噪聲（local stochastic noise）。在一個單步（time slice）內，每一個受控物理操作（閘、量測、idle）都可能伴隨獨立噪聲通道： \[ \mathcal{E}(\rho) = (1-p)\rho + \sum_i p_i E_i \rho E_i^\dagger, \] 常見簡化為：

  • 單比特 depolarizing： \[ \mathcal{D}_p(\rho) = (1-p)\rho + \frac{p}{3}(X\rho X + Y\rho Y + Z\rho Z). \]
  • 二比特 depolarizing： \[ \mathcal{D}^{(2)}_p(\rho) = (1-p)\rho + \frac{p}{15}\sum_{P\in\mathcal{P}_2\setminus\{II\}} P\rho P^\dagger. \]
  • 非對稱噪聲（\(p_X \neq p_Z\)）： \[ \mathcal{E}(\rho) = (1-p_X-p_Z)\rho + p_X X\rho X + p_Z Z\rho Z. \]

在更實際的硬體場合，也會考慮 amplitude damping、dephasing、crosstalk 等非 Pauli 噪聲，但在 Pauli twirling approximation 下，常用 Pauli channel 近似，便於與 Stim 這類 Pauli 模擬器接軌。

4.2 在 el-loom 中指定噪聲模型

el-loom 通常透過一個「噪聲規則集」來描述：

  • 對應到哪種 gate / measurement / idle。
  • 概率參數（單一標量 \(p\) 或多參數 \((p_X,p_Z,\dots)\)）。
  • 是否 time-correlated（跨周期關聯）。

概念性範例： 


from loom import noise

noise_model = noise.NoiseModel()

# 單比特 gate depolarizing
noise_model.add_gate_noise(
    gate_type="H",
    noise="depolarizing",
    p=1e-3,
)

# CNOT 的二比特 depolarizing
noise_model.add_gate_noise(
    gate_type="CNOT",
    noise="two_qubit_depolarizing",
    p=2e-3,
)

# 量測錯誤
noise_model.add_measurement_noise(
    basis="Z",
    p_meas=5e-3,
)

對應到理論分析，我們希望保證 model 中的 noise channel \(\mathcal{E}_{\text{hardware}}\) 與理論假設 \(\mathcal{E}_{\text{theory}}\) 在 diamond norm 上接近： \[ \|\mathcal{E}_{\text{hardware}} - \mathcal{E}_{\text{theory}}\|_\diamond \ll 1, \] 或至少在實驗設計中清楚說明採用之近似（如 Pauli twirling）。

4.3 時間結構與循環（cycles）

QEC 通常以 循環（cycle） 為單位：每個 cycle 執行一次完整的 syndrome measurement 序列。從邏輯態 \(\rho_L\) 開始，經過 \(T\) 個 cycle 後： \[ \rho_L^{(T)} = (\mathcal{R}\circ\mathcal{M}\circ\mathcal{N})^T (\rho_L), \] 其中：

  • \(\mathcal{N}\)：實際噪聲通道（包含 gate noise, idle noise）。
  • \(\mathcal{M}\)： syndrome measurement 與 classical post-processing（decoder input）。
  • \(\mathcal{R}\)： decoder 產生的恢復算符。

在 el-loom 的設計裡，會以「repeated circuit」或「cycle template」方式實作： 


from loom import circuits

cycle_circuit = circuits.SyndromeMeasurementCircuit.from_code(code)

# 疊加噪聲
noisy_cycle = cycle_circuit.with_noise(noise_model)

# 重複 T 次
T = 100
full_circuit = noisy_cycle.repeat(T)

此種 time-structured circuit 再交給 Stim 等底層模擬器，即可獲得對應長時間演化下的邏輯錯誤統計。

5. 測量電路設計與錯誤傳播分析

5.1 CNOT-based syndrome extraction

對於一個穩定子 \(S = \bigotimes_{j=1}^n P_j\)（其中 \(P_j\in\{I,X,Y,Z\}\)），典型的 syndrome 量測電路如下：

  1. 引入一個 ancilla qubit \(a\)，初始化為 \(\lvert 0\rangle_a\)（對 \(Z\)-type）或 \(\lvert + \rangle_a\)（對 \(X\)-type）。
  2. 對於 \(Z\)-type：
    • 對每個物理 qubit \(j\) 若 \(P_j=Z\)，執行 CNOT：\(\mathrm{CNOT}(j \rightarrow a)\)。
    • 最後量測 ancilla 在 \(Z\) 基底，得 syndrome bit。
  3. 對於 \(X\)-type：
    • 若 ancilla 在 \(\lvert + \rangle\)，則使用 \(\mathrm{CNOT}(a \rightarrow j)\) 對每個 \(P_j=X\)。
    • 最後量測 ancilla 在 \(X\) 基底。

我們可形式化地寫出 Z-type case 的測量算符： \[ M_S = \sum_{s=\pm 1} s \, \Pi_s, \] 其中 \[ \Pi_s = \frac{1}{2}(I + sS) \] 是投影到 \(S\) 本徵值 \(s\) 的 projector，被 ancilla 的演化與測量實現。錯誤傳播的重點在於 CNOT 的 Heisenberg 圖像：

  • \(\mathrm{CNOT}(c\rightarrow t)\) 下： \[ X_c \mapsto X_c X_t,\quad Z_c \mapsto Z_c,\quad X_t \mapsto X_t,\quad Z_t \mapsto Z_c Z_t. \]

因此，一個在 ancilla 上的 \(X\) 錯誤可透過 CNOT 傳到所有 target qubit 上，反之亦然。這就是為何 syndrome circuit 排程與 ancilla reuse 會嚴重影響 correlated errors 之結構。

5.2 在 el-loom 中自訂測量 schedule

el-loom 提供兩種典型策略：

  1. 自動生成 schedule： 根據穩定子的 support 與 layout，嘗試產生無衝突、深度盡量小的電路。
  2. 手動指定 schedule： 研究者自行定義多輪 CNOT 與 ancilla 使用策略，精細控制錯誤傳播結構。

一個手動指定的示意： 


from loom import circuits

builder = circuits.CircuitBuilder(code)

# 為某個 Z-type stabilizer S_1 設計量測電路
anc = builder.new_ancilla(init="0")

# round 1: CNOTs on disjoint pairs
builder.cnot(control=0, target=anc)  # Z on data 0
builder.cnot(control=3, target=anc)  # Z on data 3

# round 2: next layer
builder.cnot(control=1, target=anc)
builder.cnot(control=4, target=anc)

# measure ancilla in Z
builder.measure(anc, basis="Z")

syndrome_circuit = builder.to_circuit()

利用這種 builder 介面，可以針對：

  • 避免多個 ancilla 同時接觸相鄰 qubit（降低 correlated error）。
  • 優化 circuit depth（考量 T1/T2 decoherence）。
  • 插入 idle gate 噪聲模型。

並可將這個「局部 stabilizer 量測電路」複製到所有 face/star，組成一個完整 cycle。

6. 解碼與蒙地卡羅模擬：從 syndrome 到邏輯錯誤率

6.1 syndrome 與錯誤類別的數學結構

給定一個 Pauli 錯誤 \(E\)，其 syndrome \(s(E) \in \mathbb{F}_2^{n-k}\) 由 \[ s_i(E) = \begin{cases} 0, & \text{if } [E, S_i] = 0,\\ 1, & \text{if } \{E, S_i\} = 0, \end{cases} \] 或等價表示為 \[ s(E) = H_S J E^\top \in \mathbb{F}_2^{n-k}, \] 其中 \(E\) 以 binary symplectic 向量表示。

解碼器本質上是一個 map \[ \mathcal{D}: \mathbb{F}_2^{n-k} \to \mathcal{P}_n / S, \] 在給定 syndrome 後，輸出一個恢復操作 \(R\) 的等價類。對邏輯錯誤率感興趣的是 \(R E \notin S\) 的機率（即發生非平凡邏輯錯誤）。

6.2 蒙地卡羅估計邏輯錯誤率

假設每個 cycle 之噪聲強度為 \(p\)，我們關心的是： \[ p_L(p, d, T) = \Pr[\text{logical error after } T \text{ cycles}]. \] 蒙地卡羅流程如下：

  1. 隨機 sample 噪聲實例 \(E^{(t)}\) 在每個 cycle \(t\) 上。
  2. propagate through measurement circuit，得到 syndrome sequence \(\{s^{(t)}\}\)。
  3. 將 \(\{s^{(t)}\}\) 傳入解碼器 \(\mathcal{D}\)，取得每 cycle 的恢復操作 \(\{R^{(t)}\}\)。
  4. 最終邏輯 error operator \(L_{\text{eff}}\) 為所有 noise \& recovery 的組合，在 logical subspace 上是否為非平凡 Pauli。

利用大數法則，估計 \[ \hat{p}_L = \frac{N_{\text{logical error}}}{N_{\text{trials}}} \] 並對不同 \(p\) 與 \(d\) 取樣，進行閾值分析。

6.3 在 el-loom 中設定解碼器與模擬流程

el-loom 支援多種解碼器掛接方式，包括：

  • 內建最小重量完美匹配（MWPM）或 Union-Find 解碼器。
  • 與外部 decoder library 互通（例如開源的 PyMatching）。
  • 自訂 Python 解碼器（研究新演算法）

設定流程範例： 


from loom import decoders, simulate

decoder = decoders.MWPMDecoder.from_code(code)

sim = simulate.Simulator(
    code=code,
    cycle_circuit=cycle_circuit,
    noise_model=noise_model,
    decoder=decoder,
)

results = sim.run(
    p=5e-3,
    n_trials=10_000,
    n_cycles=100,
)
print(results.logical_error_rate)

在高階研究中，重點通常不是單一點的 \(p_L\)，而是：

  • 固定 \(d\)，掃描 \(p\) → 畫出 \(p_L\) vs. \(p\) 曲線。
  • 對多個 \(d\) 重複 → 找到 crossing point → 閾值估計。
  • 分析 \(p_L(p)\) 的漸近斜率（如 \(p_L \sim (p/p_{\text{th}})^{(d+1)/2}\)）。

7. 閾值與縮放律分析：多碼距實驗設計

7.1 閾值的嚴謹定義與 scaling ansatz

一個 QEC code family \(\{\mathcal{C}_d\}\)（如距離 \(d=3,5,7,\dots\) 之 surface code）在某種噪聲模型下有閾值 \(p_{\text{th}}\)，若存在 \(p_{\text{th}} > 0\) 使得： \[ \forall\, p < p_{\text{th}}: \quad \lim_{d\to\infty} p_L(p,d) = 0. \] 另一方面，若 \(p > p_{\text{th}}\)，則 \(\liminf_{d\to\infty} p_L(p,d) > 0\)。

在數值實驗中，常假設近閾值區域遵守 scaling ansatz： \[ p_L(p,d) \approx f\left( (p-p_{\text{th}}) d^{1/\nu} \right), \] 其中 \(\nu\) 為相關長度臨界指數，\(f\) 為某 universal scaling function。對 fixed \(d\) 掃描 \(p\)，再對不同 \(d\) 作 collapse 分析，可同時估計 \(p_{\text{th}}\) 與 \(\nu\)。

7.2 在 el-loom 中設計多距離碼族與批次模擬

規劃一個完整的閾值研究通常需要：

  1. 選擇一系列距離 \(d \in \{d_{\min},\dots,d_{\max}\}\)。
  2. 對應每個 \(d\) 建立一個 code instance \(\mathcal{C}_d\)。
  3. 選定一組物理錯誤率 grid：\(p\in\{p_1,\dots,p_M\}\)。
  4. 為每個 \((d,p)\) 組合進行 \(N\) 次蒙地卡羅試驗，估計 \(p_L(d,p)\)。
  5. 將所有結果存至統一資料結構（例如 pandas.DataFrame）以利分析。

在 el-loom 中可以利用 loops + config 驅動： 


from loom import codes, simulate, decoders

distances = [3, 5, 7]
phys_ps = [2e-3, 3e-3, 4e-3, 5e-3]

records = []

for d in distances:
    code_d = codes.SurfaceCode(distance=d)  # 或自訂家族生成
    decoder_d = decoders.MWPMDecoder.from_code(code_d)
    sim_d = simulate.Simulator(
        code=code_d,
        cycle_circuit=code_d.default_cycle_circuit(),
        noise_model=noise_model,
        decoder=decoder_d,
    )
    for p in phys_ps:
        res = sim_d.run(
            p=p,
            n_trials=20_000,
            n_cycles=round(d),  # 或更複雜的 T(d) 選擇
        )
        records.append({
            "distance": d,
            "p_phys": p,
            "p_log": res.logical_error_rate,
            "stderr": res.stderr,
        })

為了避免「在閾值附近需要非常多樣本」的問題，常採用 adaptive sampling 或 importance sampling，el-loom 也可能提供：

  • 基於 target confidence interval 的自動停止條件。
  • 支援 Stim 的 --count-logical-errors / --sample 高效統計介面。

7.3 結果分析與交叉驗證

當得到 \(p_L(d,p)\) 的資料後，數學上要處理：

  • 適當的誤差條（standard error）： \[ \sigma_{p_L} = \sqrt{\frac{p_L(1-p_L)}{N_{\text{trials}}}}. \]
  • 使用加權最小平方擬合 crossing point。
  • 檢查不同 decoder / noise model 下 \(p_{\text{th}}\) 是否穩定（robustness）。
  • 和理論預測（如 self-dual code 的對稱性、對應統計物理模型的臨界點）對照。

8. 自訂碼設計實驗：從幾何到代碼優化

8.1 問題設定：為非對稱噪聲設計最佳碼

考慮一個具體研究問題：

給定一個硬體噪聲模型，其 \(Z\)-錯誤遠多於 \(X\)-錯誤（如 dephasing-dominated noise），希望設計一個在固定 qubit 數下最小化長時間邏輯錯誤率的穩定子碼。

數學上，我們可以將噪聲通道 parameterize 成： \[ \mathcal{E}(\rho) = (1-p_Z - p_X)\rho + p_X X\rho X + p_Z Z\rho Z \] 並假設 \(p_Z \gg p_X\)。對一個代碼 \(\mathcal{C}\)，可定義「X-type distance」與「Z-type distance」：

  • \(d_X\)：造成 \(\overline{X}\) 邏輯錯誤的最小 Z-type 錯誤 weight。
  • \(d_Z\)：造成 \(\overline{Z}\) 邏輯錯誤的最小 X-type 錯誤 weight。

在 \(p_Z \gg p_X\) 下，我們希望 \(d_X \gg d_Z\)，即對 dominating noise 方向拉高距離。

8.2 幾何設計空間與搜尋策略

在 el-loom 中，可以設計一個 parametric code family：

  • 幾何參數：如長寬比 \(L_x \times L_y\) 的 rectangular surface code。
  • 邊界型態：smooth/rough 邊界組合。
  • 穩定子選擇：是否引入變形 plaquette/star。

例如 rectangular surface code 中： \[ d_X = L_x, \quad d_Z = L_y \] （視具體邊界選擇而定），則在 \(p_Z \gg p_X\) 時可選擇 \(L_x \gg L_y\) 以優化。

圖 5-4: Illustration of rectangular surface code patches with different aspect ratios Lx x Ly. Highlight logical X and Z operators as string-like paths, indicating their lengths correspond to d_X and d_Z, respectively. Show that increasing one dimension increases one logical distance.
Prompt: Illustration of rectangular surface code patches with different aspect ratios Lx x Ly. Highlight logical X and Z operators as string-like paths, indicating their lengths correspond to d_X and d_Z, respectively. Show that increasing one dimension increases one logical distance.

在 el-loom 內，可這樣 parametrize： 


def make_rect_surface(Lx, Ly):
    return codes.SurfaceCode(
        size_x=Lx,
        size_y=Ly,
        boundaries=("rough", "smooth"),  # example
    )

# 搜尋在固定 qubit 數下的最佳 Lx, Ly
budget = 100  # qubit budget
candidates = []
for Lx in range(3, 11, 2):
    for Ly in range(3, 11, 2):
        code = make_rect_surface(Lx, Ly)
        if code.n_qubits <= budget:
            candidates.append((code, Lx, Ly))

8.3 以 el-loom 進行自動化比較實驗

對每個候選 \((L_x,L_y)\) 之 code instance，我們可：

  1. 採用同一噪聲模型（非對稱 \(p_Z,p_X\)）。
  2. 使用固定解碼器（如 MWPM with anisotropic weights）。
  3. 在一組 \(p\) or \((p_X,p_Z)\) 參數下估計 \(p_L\)。
  4. 比較在相同 qubit 數下的 performance。

官能定義為例如： \[ F(\mathcal{C}) = p_L(p_X,p_Z, T; \mathcal{C}), \] 以「越小越好」為優化目標。在 el-loom 的 Python 環境中可直接寫： 


best = None

for code, Lx, Ly in candidates:
    decoder = decoders.MWPMDecoder.from_code(code)
    sim = simulate.Simulator(
        code=code,
        cycle_circuit=code.default_cycle_circuit(),
        noise_model=noise_model,
        decoder=decoder,
    )
    res = sim.run(
        p=None,  # 這裡可直接以 p_X, p_Z 傳入
        p_X=1e-4,
        p_Z=1e-3,
        n_trials=50_000,
        n_cycles=200,
    )
    score = res.logical_error_rate
    if (best is None) or (score < best["score"]):
        best = {
            "code": code,
            "Lx": Lx,
            "Ly": Ly,
            "score": score,
        }

print("Best aspect ratio:", best["Lx"], best["Ly"], "with p_L=", best["score"])

這類 parametric search 實驗，在過往文獻中常用於：

  • 變形 surface code / XZZX code 的性能比較。
  • 幾何限制下（例如可用 coupler 的拓樸）尋找最佳 tiling。
  • 探索 fracton-like code 或嵌入在 3D layout 的 code 結構。

9. 高階議題：自訂解碼器與資料匯出

9.1 將 syndrome / error history 輸出給外部解碼器

許多新型解碼器（machine learning-based, tensor networks 等）並非原生整合在 el-loom 內。典型 workflow 是：

  1. 使用 el-loom + Stim 產生 syndrome samples。
  2. 將 syndrome 時間序列或 graph representation 匯出成檔案（如 JSON, HDF5）。
  3. 在獨立環境（PyTorch, JAX）訓練或執行 decoder。
  4. 將解碼結果回傳或離線分析邏輯錯誤率。

示意： 


samples = sim.sample_syndromes(
    n_samples=100_000,
    n_cycles=50,
    return_errors=True,  # 同時輸出實際 error operator
)

# 將 samples 轉為 NumPy/Tensor
import numpy as np
syndrome_array = np.array(samples["syndromes"])  # shape (N, T, n_stab)
error_labels = np.array(samples["logical_errors"])  # 0/1 per sample

# 儲存或直接送入 ML 模型
np.savez("qec_dataset.npz",
         syndromes=syndrome_array,
         labels=error_labels)

9.2 自訂 Python 解碼器與 el-loom 的介面

若希望直接在 el-loom 之內實作一個 prototype decoder，可以實作一個介面類別，例如： 


from loom.decoders import BaseDecoder

class MyCustomDecoder(BaseDecoder):
    def __init__(self, code, params):
        super().__init__(code)
        self.params = params
        # 可於此建構 syndrome graph, precompute tables, etc.

    def decode(self, syndrome_history):
        # syndrome_history: shape (T, n_stabilizers)
        # 回傳一個 Pauli operator (e.g., textual or binary)
        # 這裡示意 return identity (不做矯正)
        return "I" * self.code.n_qubits

# 使用
decoder = MyCustomDecoder(code, params={...})
sim = simulate.Simulator(..., decoder=decoder)

此介面允許：

  • 在 simulator 內部直接呼叫 decode，獲得每 cycle 的恢復操作。
  • 比較不同 decoder class 在同一 code, noise model 下的性能。
  • 對 decoder 的 parameter \(\theta\) 做 sweep 或最適化。

11. 小結與延伸方向

本課程從穩定子碼的嚴謹數學定義出發，說明如何將其映射到 el-loom 的資料結構與模擬流程，並展示高階研究者在「自訂代碼與設計實驗」時可採用的完整 pipeline：

  1. 設計或選擇一個 code family，建立其穩定子與邏輯算符表示。
  2. 在 el-loom 中定義 code + layout，生成或自訂測量電路與 schedule。
  3. 建模噪聲通道（包含非對稱、時間結構、硬體特有效應）。
  4. 選擇與實作解碼器，使用蒙地卡羅模擬估計邏輯錯誤率。
  5. 設計多碼距、多參數掃描實驗，進行閾值與 scaling 分析。
  6. 利用 parametric search 探索最佳代碼幾何或結構（如非對稱碼）。
  7. 將 syndrome/data 匯出，連接外部 ML 或 tensor-network 解碼器。
  8. 透過 config 驅動與良好專案結構，確保實驗的可重現性。

下一步你可以嘗試：

  • 實作一個小型但 novel 的自訂碼（例如帶 dislocation 的 surface code），在 el-loom 中完整建立並比較其性能。
  • 針對具體硬體參數（實驗室提供的 T1/T2, gate fidelity, readout error）建立 realistic noise model，重新評估某碼族的實用閾值。
  • 將 el-loom 產生的 syndrome history 匯出，訓練一個 neural decoder，與傳統 MWPM 作系統性比較。

隨著 el-loom 與周邊工具的演進，這套工作流程可以輕易擴展至 concatenated codes、LDPC codes、subsystem codes 等更複雜的架構，在理論與實務之間搭建更順暢的橋梁。
