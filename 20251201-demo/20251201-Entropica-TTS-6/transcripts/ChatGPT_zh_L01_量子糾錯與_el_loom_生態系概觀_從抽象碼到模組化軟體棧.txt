 3.3 為何需要 Rust + Python 的雙層架構？

 解碼器之間的效能差異常受「實作細節」大幅影響：例如 MWPM 的 Hopcroft–Karp 或 Blossom 演算法，
 在大型表面碼下可能涉及上百萬個節點與邊。使用 Rust 可達到：

 接近 C/C++ 的執行效率。

 在所有權系統下較安全的記憶體管理。

 更易於封裝為動態函式庫供其他語言呼叫。

 相對地，研究者多習慣使用 Python 進行快速原型與資料分析。
 el-loom 利用 Rust 的 FFI 將核心函式暴露給 Python：
 Python 經由 FFI 映射到 Rust core。

 使得使用者可以在 Python 裡撰寫：

from loom.codes import SurfaceCode
from loom.noise import DepolarizingNoise
from loom.decoders import MWPMDecoder
from loom.simulation import run_trial

code = SurfaceCode(distance=5)
noise = DepolarizingNoise(p=0.001)
decoder = MWPMDecoder(code, noise)

logical_failure = run_trial(code, noise, decoder)

 而真正的大筆運算，如 syndrome 圖構造、圖匹配等，則在 Rust 裡執行。
 這種分工是現代科學運算常見的模式（類似 JAX/XLA、PyTorch/C++ core）。

 5.2 碼與噪聲的程式化表示：一個具體例子

 以下示意如何在 el-loom 的 Python API 中定義一個表面碼與簡單噪聲模型
 （介面名稱僅為說明性，實際以官方文件為準）：

from loom.codes import RotatedSurfaceCode
from loom.noise import DepolarizingNoise
from loom.decoders import MWPMDecoder
from loom.simulation import MonteCarloSimulator

# 1. 建構碼
d = 5
code = RotatedSurfaceCode(distance=d)

# 2. 定義噪聲：每個物理比特獨立 depolarizing 機率 p
p = 0.001
noise_model = DepolarizingNoise(p=p)

# 3. 定義 syndrome 測量輪數
rounds = 1 # 單輪，對靜態錯誤模型

# 4. 選擇解碼器
decoder = MWPMDecoder(code=code, noise_model=noise_model, rounds=rounds)

# 5. 建立蒙地卡羅模擬器
sim = MonteCarloSimulator(code, noise_model, decoder)

# 6. 執行 N 次試驗，估計 logical error rate
N = 10_000
logical_failures = 0

for _ in range(N):
 result = sim.run_trial()
 if result.logical_error_occurred:
 logical_failures += 1

logical_error_rate = logical_failures / N
print("Logical error rate:", logical_error_rate)

 這段流程在底層等價於多次重複以下操作：

 抽樣錯誤 E 波浪號 p 括號 E 括號。
。

 計算 syndrome 粗體的 s，小括號裡面一個 E。
。

 使用解碼器產生補償 E 帽等於 D 括號裡面的小寫粗體的 s，作用在大寫的 E 上。
。

 檢查 E 乘上 E 帽。
 是否等於某個非平凡邏輯運算子。

 形式上，邏輯錯誤的事件可表述為
 C of E 定義成 E 乘上 D 括號裡面是粗體的 s of E，然後它屬於 N 的括號 S 裡面，但不在 S 裡面。

 其中 C 括弧 E 括弧起來。
 為最終殘餘錯誤。若 C 括弧 E 括弧起來。
 屬於邏輯子群而非穩態群，
 則表示邏輯資訊被翻轉。
