4.2 Using a Pre-Built Surface Code Family

el-loom typically provides a surface code family, such as planar codes of distance d
. Conceptually, one can do:

from loom.codes import SurfaceCode

d = 3 # code distance
code = SurfaceCode(distance=d, boundary='planar')

Internally, this constructs:

 Data qubits: corresponding to lattice edges.

 Ancilla qubits: corresponding to each X-/Z-type stabilizer.

 Stabilizer generator data structures, including:

 Type (X or Z stabilizer).

 The list of data qubits it acts on.

 Ancilla qubit index.

If researchers need deformed lattices (e.g., rotated surface codes, heavy-hex codes, etc.), they can use the lower-level el-loom API to define the geometry relating qubits and checks directly. This is quite important in advanced research because the actual hardware topology is rarely a perfect square lattice.

5. Constructing Measurement Cycles in el-loom

5.1 Abstract Description of a Measurement Cycle

At an abstract level, one round of a surface code measurement cycle consists of:

 Initializing all ancilla qubits:

 Ancillas for X-stabilizers are initialized to Ket plus.
.

 Ancillas for Z-stabilizers are initialized to Ket zero.
.

 Applying a sequence of CNOTs to each stabilizer according to a fixed schedule:

 For Z-stabilizers: CNOT(data → ancilla).

 For X-stabilizers: CNOT(ancilla → data).

 Measuring all ancillas:

 Ancillas of Z-stabilizers are measured in the Z-basis.

 Ancillas of X-stabilizers are measured in the X-basis (equivalently, apply a Hadamard before and after a Z-basis measurement).

In el-loom, this is typically encapsulated in a “cycle object” or “measurement round” description, which is then translated to a low-level sequence of gates (a gate list or circuit object). For example (schematically):

from loom.circuits import MeasurementCycleBuilder

builder = MeasurementCycleBuilder(lattice=lat)

cycle = builder.build_standard_surface_code_cycle(
 schedule='canonical', # or 'checkerboard', custom, etc.
)

Here the schedule parameter determines the time slots of the CNOTs, ensuring that no qubit participates in more than one gate at the same time, while keeping the total circuit depth as low as possible. For standard square lattice surface code implementations, 4-step or 8-step CNOT schedules are commonly used.

5.2 Circuit-Level Implementation: Initialization, Gates, and Measurement

At a lower-level API, one cycle can be described as a sequence of gate operations, for example:

from loom.circuits import Circuit

circ = Circuit()

# 1. Initialize ancillas
for q in ancilla_z:
 circ.add_reset(q, basis='Z') # |0>
for q in ancilla_x:
 circ.add_reset(q, basis='X') # |+>, often implemented as |0> then H

# 2. CNOT scheduling
for timeslot in schedule:
 for (ctrl, tgt) in timeslot.cnot_pairs:
 circ.add_cnot(ctrl, tgt)

# 3. Measure ancillas
for q in ancilla_z:
 circ.add_measure(q, basis='Z')
for q in ancilla_x:
 circ.add_measure(q, basis='X')

In the surface code, one typically arranges that stabilizers of the same type (e.g., all X-stabilizers or all Z-stabilizers) share the same “CNOT layer structure”. For standard surface codes, el-loom usually provides a default schedule, which researchers only need to override or extend when necessary.

6. Adding Noise in el-loom: Circuit-Level Noise Models

6.1 Structure of Noise Models

el-loom provides a variety of noise model components, which can be conceptually decomposed into:

 Single-qubit gate noise: e.g., apply a Pauli channel after every 1-qubit gate.

 Two-qubit gate noise: e.g., apply a two-qubit depolarizing channel after every CNOT.

 Idle / decoherence noise: apply noise induced by T one over T two
 during idle time slots.

 Measurement errors: classical readout flips or non-ideal projective measurements.

Mathematically, noise can be described using Kraus operators or superoperators. For the commonly used two-qubit depolarizing channel, we have:
Calligraphic D sub p superscript two of rho equals one minus p times rho plus p over fifteen times the sum over all P in calligraphic P sub two excluding the identity I I of P rho P.

This can approximate the noise of a CNOT gate in real hardware. el-loom associates this with a specific gate to form a noisy gate model:

U tilde sub CNOT of rho equals script D sub p superscript two of open parenthesis U sub CNOT, rho, U sub CNOT dagger, close parenthesis.

6.2 Configuring Noise Models in el-loom

In code, one typically first creates a noise configuration and then attaches it to the circuit simulator, for example:

from loom.noise import NoiseModel

noise = NoiseModel()

# Single-qubit gate noise
noise.set_1q_gate_noise(
 p=1e-4, # error probability
 model='depolarizing'
)

# Two-qubit gate noise (e.g., CNOT)
noise.set_2q_gate_noise(
 p=5e-3,
 model='depolarizing'
)

# Measurement error: readout bit-flip
noise.set_measurement_noise(
 p=1e-3,
 model='bitflip'
)

# Idle noise / T1T2
noise.set_idle_noise(T1=50e-6, T2=60e-6, gate_time=20e-9)

Then, for running measurement-cycle simulations:

from loom.sim import CircuitSimulator

sim = CircuitSimulator(noise_model=noise)

# Build measurement cycle circuit
cycle = builder.build_standard_surface_code_cycle(...)

# Run T rounds
T = 20
syndrome_records = []
state = code.initial_state() # or logical |0_L>, etc.

for t in range(T):
 result = sim.run(cycle, init_state=state)
 syndrome_records.append(result.syndrome)
 state = result.final_state # optional, if tracking full state

For large codes or long time series, fully tracking the density matrix or state vector is too costly; el-loom typically employs more efficient techniques such as Pauli frame tracking or stabilizer simulation. Mathematically, many standard noise models (Pauli channels) are closed under Clifford circuits (the stabilizer formalism is closed under Clifford gates and Pauli noise), allowing the tracking of syndromes and the evolution of logical operators with complexity Big O of n cubed.
 or better.

6.3 Statistical Properties of Syndrome Time Series

In the presence of noise, the observed syndrome bold s with a superscript t
 no longer depends solely on data-qubit errors; measurement and ancilla errors also contribute “noise” to the syndrome. Ideally, for each measurement round we have:
Bold s to the t equals bold s data to the t XOR bold s meas to the t.

where bold s sub data superscript t
 is determined by data-qubit errors accumulated over the current and previous rounds, and bold s sub meas superscript t
 captures “false positives” caused by measurement / ancilla errors. In the time dimension, typical decoders use space–time graph structures; for example, 3D MWPM treats changes in the syndrome as “defect endpoints” and performs matching in space–time.

In el-loom, we can directly access the syndrome for each round:

# syndrome_records[t][i]: i-th stabilizer outcome at round t

These syndromes can then be fed to external decoders (such as the Python interface of PyMatching). Here, el-loom mainly provides accurate syndrome time series that incorporate circuit-level noise.

8. In-Depth: Effects of Cycle Structure on Error Thresholds and Comparative Experiments in el-loom

8.1 Comparing Different Measurement Cycle Schemes

In theory, as long as a circuit correctly implements the stabilizer measurement POVM, different cycle schemes are equivalent in the absence of noise. However, in realistic noisy settings:

 Different schedules can give rise to different error propagation paths (e.g., hook errors).

 Some designs can reduce the extent to which a single-qubit error spreads into weight-2 or higher-weight correlated errors.

 Certain schemes allow local modifications to better respect hardware connectivity constraints.

These differences directly manifest in the logical error rates and threshold estimates. el-loom is an ideal tool for such comparisons: we can implement multiple cycle variants, simulate them under the same noise model, and compare their logical failure probabilities.

8.2 Implementing Multiple Cycles and Comparing Them in el-loom

8.3 Mathematical Understanding of Hook Error Suppression

So-called hook errors refer to situations where, due to a particular CNOT scheduling pattern, a single physical error (for example, an error on an ancilla) is propagated through multiple CNOT gates onto several data qubits, forming a “hook-shaped” error chain whose weight may approach or equal the code distance, thus making it more difficult for the decoder to detect.

Formally, if an X sub a
 error occurs on an ancilla a
, and we perform two consecutive CNOTs (with a
 as control and d one, d two
 as targets):
X sub a, goes to, under a CNOT from a to d one, X sub a X sub d one, which then goes to, under a CNOT from a to d two, X sub a X sub d one X sub d two.

Further entanglement with other CNOTs can lead to weight-3 or even higher-weight correlated errors. By carefully designing the schedule to ensure that a given Pauli error only propagates within a “short range”, one can suppress hook errors to some extent and thereby improve the threshold.

el-loom allows us to inject a single Pauli error precisely at the circuit level and track its final effect. For example:

from loom.debug import inject_pauli_error

 schedule='candidate_schedule'
)

res = sim.run(inj_cycle, init_state=code.logical_state('0'),
 noise_model=None) # no additional noise

final_pauli = analyze_final_error(res)
print("Effective weight of propagated error:", final_pauli.weight())

In this way we can compare hook-error propagation behavior under different schedules and use it to optimize the measurement cycle both theoretically and in practice.

 A bridge from abstract codes to concrete circuits: it can automatically translate high-level stabilizer descriptions into executable circuits and measurement cycles.

 Integration with decoders: it can output syndrome time series to specialized decoders for threshold and fault-tolerance architecture studies.

 Extensible lattices and code families: it can implement modern architectures such as rotated surface codes and heavy-hex codes.

 Connecting el-loom to higher-level fault-tolerant schemes (such as lattice surgery and magic state distillation) to perform end-to-end fault-tolerance cost estimates.
