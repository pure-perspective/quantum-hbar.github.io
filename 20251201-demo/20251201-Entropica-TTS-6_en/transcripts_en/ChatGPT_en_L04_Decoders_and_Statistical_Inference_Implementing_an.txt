2. Decoding Abstractions in el-loom: DecodingTask and Decoder Interfaces

el-loom provides modular abstractions for decoding, whose core components are:

 DecodingTask: defines “what is to be decoded” — the code, noise, number of measurement rounds, whether time correlations are considered, etc.

 Decoder: defines “how to decode” — mapping from the syndrome (and possibly auxiliary information) to a recovery or a logical guess.

 Sampler / Experiment: generates samples (errors, syndromes, logical outcomes) used to estimate decoder performance.

In a typical workflow:

 Define the quantum code and the noise model.

 Construct a DecodingTask (for example, a cyclic code under i.i.d. depolarizing noise).

 Select or implement a Decoder.

 Use the sampling tools in el-loom to generate many trials and estimate logical error rates, thresholds, etc.

6. Multi-Round Measurements and Space-Time Decoding

6.1 Syndrome History as a Three-Dimensional Graphical Structure

On actual quantum hardware, stabilizer measurements are themselves noisy, and multi-round syndrome measurements are typically employed. Each round’s syndrome bold s sub t
 (t equals one, comma, dot dot dot, comma, capital T.
) can be viewed as a 2D lattice on a time slice. Errors can occur on:

 Data qubits: causing syndromes to remain flipped over time.

 Measurement qubits / readout: causing syndromes to flip once in time (a transient flip).

As a result, a single error no longer affects only the syndrome in one round; instead, it induces adjacency relations along the time dimension. This can be embedded in a 3D lattice (2D space + 1D time), where one can apply 3D matching or other 3D decoders.

7.2 Consistent Design across Multiple Codes and Noise Models

A key advantage of el-loom is that the same DecodingTask / Decoder abstractions apply to many different codes (surface, color, quantum LDPC, etc.) and noise models (i.i.d., biased, correlated, circuit-level). Thus, when designing custom decoders, we recommend the following principles:

 Decouple from specific code structure: encapsulate code-specific information during construction (e.g., via precompute_neighborhoods), rather than hard-coding indices in the decode function.

 Decouple from the noise model: if the decoder needs additional noise parameters, pass them via the constructor (e.g., pZ, pX, correlations) instead of reading them directly from an internal noise object.

 Decouple from sampling/experiments: the decoder should only care about input syndromes and output decisions, not about how experiments estimate error rates.

With this design, we have
Decoder, from syndrome space and hyperparameters to decision space.

which can be reused across arbitrary DecodingTasks, maximizing fairness and reproducibility in experimental comparisons.

9.2 Interpretation from the Perspective of Statistical Inference

If, under biased noise, the neural decoder’s curves clearly outperform those of MWPM, this indicates that it has, in some sense, produced a more accurate estimate of the posterior

. This reflects:

 The factorization assumptions underlying MWPM (independence, shortest path ≈ highest probability) become seriously invalid in biased or correlated regimes.

 The ML-based model learns decision boundaries in the high-dimensional syndrome space that more closely approximate the true posteriors.

The BP decoder may perform in between the two in moderately biased regimes, as it partially accounts for parity constraints and prior bias but is still limited by loops and factorization assumptions.

This illustrates that decoder design = statistical assumptions about noise and syndrome structure + computationally feasible trade-offs. el-loom enables us to quantify and compare the effects of different statistical assumptions under clearly specified experimental settings, providing data-driven support for further theoretical analysis.
