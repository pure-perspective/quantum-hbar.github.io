1. The Decoding Problem as a Statistical Inference Problem

1.1 From Stabilizer Measurements to Conditional Probabilities

Consider a stabilizer code whose stabilizer group is denoted by \( \mathcal{S} \subset \mathcal{P}_n \) (the \(n\)-qubit Pauli group), with codespace \[ \mathcal{C} = \{ \lvert \psi \rangle \,:\, S \lvert \psi \rangle = \lvert \psi \rangle,\ \forall S \in \mathcal{S} \}. \] A noise channel \( \mathcal{N} \) acts on the physical state, and we measure the stabilizer generators \( \{ S_1, \dots, S_m \} \) to obtain a syndrome vector \[ \mathbf{s} = (s_1, \dots, s_m) \in \{\pm 1\}^m. \] The task of the decoder is to infer a recovery operator \( R(\mathbf{s}) \) based on \( \mathbf{s} \), in such a way that the resulting logical error after recovery is minimized.

A typical assumption is that the noise is composed of Pauli errors (or can be Pauli-twirled). Let \( E \in \mathcal{P}_n \) denote some Pauli error. The syndrome is determined by the error: \[ s_i = \pm 1,\quad \text{such that } S_i E = s_i E S_i. \] Thus, the syndrome is a linear piece of information about the error, and decoding is essentially:

  • Given a noise model \(p(E) = \Pr(E)\),
  • given a syndrome \( \mathbf{s} \),
  • obtain an “optimal” recovery decision from the posterior distribution \( \Pr(E \mid \mathbf{s}) \).

Formally, by Bayes’ rule: \(E\) given bold s equals probability of bold s given \(E\) times probability of \(E\), divided by probability of bold s.-->\[ \Pr(E \mid \mathbf{s}) = \frac{\Pr(\mathbf{s} \mid E)\Pr(E)}{\Pr(\mathbf{s})}. \] Under ideal syndrome measurements, if the syndrome corresponding to \(E\) is \(\mathbf{s}(E)\), then \[ \Pr(\mathbf{s} \mid E) = \begin{cases} 1, & \mathbf{s} = \mathbf{s}(E),\\ 0, & \text{otherwise.} \end{cases} \] Therefore, the posterior distribution is supported on the set of all errors consistent with \(\mathbf{s}\): \[ \mathcal{E}(\mathbf{s}) = \{E \in \mathcal{P}_n : \mathbf{s}(E) = \mathbf{s}\}. \]

Fully optimal decoding (Maximum Likelihood / Maximum A Posteriori, ML/MAP) amounts to finding \[ E^\star(\mathbf{s}) = \arg\max_{E \in \mathcal{E}(\mathbf{s})} \Pr(E). \] However, in practice, we are more sensitive to logical errors. Let \( \bar{L} \) be a logical Pauli operator. Two errors \(E, E'\) that differ only by a stabilizer, i.e. \(E' = E S\) for some \(S \in \mathcal{S}\), are equivalent on the codespace: \[ E' \sim E. \] What really matters for decoding are the “error equivalence classes,” or, which logical operator is induced.

1.2 MAP Decoding at the Logical Level

Define the logical error class \( [E] \) by \[ [E] = E \cdot \mathcal{S} = \{ E S : S \in \mathcal{S} \}. \] Given a syndrome \(\mathbf{s}\), the errors that produce the same syndrome can be partitioned into several logical equivalence classes \( [E_\alpha] \), each corresponding to a logical Pauli: \[ \mathcal{E}(\mathbf{s}) = \bigsqcup_{\alpha} [E_\alpha] \cap \mathcal{E}(\mathbf{s}). \] The posterior probability at the logical level is then quantified as \[ \Pr([E_\alpha] \mid \mathbf{s}) = \sum_{E \in [E_\alpha] \cap \mathcal{E}(\mathbf{s})} \Pr(E \mid \mathbf{s}). \] The optimal logical MAP decoder selects the logical class with maximum posterior probability \[ \alpha^\star(\mathbf{s}) = \arg\max_\alpha \Pr([E_\alpha] \mid \mathbf{s}), \] and chooses any representative as the recovery: \[ R(\mathbf{s}) \in [E_{\alpha^\star(\mathbf{s})}]. \] This is the optimal decoding criterion for minimizing the logical error rate.

Intuitively, we seek to answer the question: “Given the observed syndrome, which logical error class is most likely to have occurred?” Viewing decoding as an inference problem over this probability distribution provides a natural interface to machine learning and statistical methods.

2. Decoding Abstractions in el-loom: DecodingTask and Decoder Interfaces

el-loom provides modular abstractions for decoding, whose core components are:

  • DecodingTask: defines “what is to be decoded” — the code, noise, number of measurement rounds, whether time correlations are considered, etc.
  • Decoder: defines “how to decode” — mapping from the syndrome (and possibly auxiliary information) to a recovery or a logical guess.
  • Sampler / Experiment: generates samples (errors, syndromes, logical outcomes) used to estimate decoder performance.

In a typical workflow:

  1. Define the quantum code and the noise model.
  2. Construct a DecodingTask (for example, a cyclic code under i.i.d. depolarizing noise).
  3. Select or implement a Decoder.
  4. Use the sampling tools in el-loom to generate many trials and estimate logical error rates, thresholds, etc.

2.1 Constructing a DecodingTask: Example Structure

(The following code fragments are conceptual examples; please refer to the official documentation for the actual API.)


from loom import codes, noise, tasks

# 1. Build a code model, e.g., an LxL planar surface code
code = codes.PlanarSurfaceCode(distance=d)

# 2. Build a noise model
channel = noise.DepolarizingNoise(p_error=p)

# 3. Construct a DecodingTask
task = tasks.DecodingTask(
    code=code,
    noise_model=channel,
    n_rounds=1,           # single-round syndrome
    phenomenological=False  # or True to add errors directly on the syndrome
)

A DecodingTask implicitly defines:

  • The observable syndrome space \( \mathcal{S} \).
  • The set of possible errors (or the sampling process over errors).
  • The logical observables (such as logical \(X\)/\(Z\) flips).

Mathematically, you can think of it as specifying a joint distribution \[ \Pr(E, \mathbf{s}, L) \quad \text{under a given code + noise}, \] where \(L\) describes the logical error (for example \((\ell_X, \ell_Z)\in \{0,1\}^2\)).

2.2 The Decoder Interface and Signature

A typical decoder object in el-loom provides an interface of the form \[ \texttt{decoder.decode(syndrome)} \mapsto \texttt{recovery or logical guess}. \] Depending on the task, this may mean:

  • Outputting a recovery Pauli \(R\), letting the framework determine whether it induces a logical error.
  • Directly outputting a logical error guess \(\hat{L}\), without explicitly giving a physical recovery.
  • For multi-round, time-resolved syndromes (3D matching), the input is the entire syndrome history.

For researchers, the key point is that the Decoder is abstracted as a pure function: observation \(\to\) decision. This makes it easy to compare different algorithms under the same DecodingTask. 


from loom import decoders

decoder = decoders.SomeDecoder(task)

syndrome = task.sample_syndrome()  # or loaded from experimental data
decision = decoder.decode(syndrome)

3. Maximum Likelihood Decoding and MWPM: From Statistical Models to Matching Graphs

3.1 Independent Edge Weights under i.i.d. Pauli Noise

Consider a 2D surface code under i.i.d. Pauli noise. Assume a single-qubit error model: \(p\); probability that \(E_j\) equals \(X\) equals probability that \(E_j\) equals \(Y\) equals probability that \(E_j\) equals \(Z\) equals \(p\) over three.-->\[ \Pr(E_j = I) = 1-p,\quad \Pr(E_j = X) = \Pr(E_j = Y) = \Pr(E_j = Z) = \frac{p}{3}, \] with errors on different qubits being independent. Then the probability of a global error \(E = \bigotimes_{j=1}^n E_j\) is \[ \Pr(E) = \prod_{j=1}^n \Pr(E_j). \] Here, the syndrome \( \mathbf{s} \) is typically equivalent to the set of defects (violated stabilizers) generated by Pauli errors. For X/Z stabilizers in the surface code, the syndrome changes induced by errors can be interpreted as error edges (on the dual/primal lattice) connecting two excitations (ignoring logical boundaries for the moment).

If we focus on single-type errors (e.g., pure Z errors corresponding to X-type syndromes), then the error can be viewed as a subset of lattice edges \(E \subseteq \mathcal{E}\) (the edge set of a graph). Each edge \(e\) represents a Z error on that edge, flipping two neighboring X stabilizers. Then: \[ \Pr(E) = \prod_{e \in E} p_e \prod_{e \notin E} (1-p_e), \] where for an i.i.d. model, \(p_e = p\).

Given a syndrome (i.e., given which stabilizers have flipped), different error sets \(E\) correspond to different ways of pairing up the syndrome defects (matching) by connecting them (or connecting them to logical boundaries). The idea of MWPM (minimum-weight perfect matching) decoding is to simplify the difference in \[ -\log \Pr(E) = \sum_{e \in E} -\log p_e + \sum_{e \notin E} -\log(1-p_e) \] to only depend on the set of edges used, via a “weight” \[ w_e = \log\frac{1-p_e}{p_e}. \] Thus, maximum likelihood decoding is equivalent to finding the
matching between defects with minimum total edge weight.

In the i.i.d. case, all edge weights are identical (or depend only on distance), reducing the graph structure to a standard MWPM problem that can be solved by polynomial-time algorithms such as Blossom.

3.2 The MWPM Decoder in el-loom

el-loom provides MWPM-like decoders that encapsulate the process of building a matching graph from the syndrome and invoking a back-end matching solver. A typical usage pattern (schematic) is: 


from loom import decoders

mwpm_decoder = decoders.MWPMDecoder(task)

syndrome = task.sample_syndrome()
recovery = mwpm_decoder.decode(syndrome)

# Evaluate the logical error
logical_error = task.logical_effect(recovery, syndrome)

Abstractly, the internal procedure consists of three steps:

  1. Project the syndrome defects onto some graph as a set of vertices \(V_s \subseteq V\).
  2. For each pair of defects \((u,v)\), create an edge whose weight corresponds to the negative log-probability of the associated error path.
  3. On this graph, compute a minimum-weight perfect matching to obtain a set of edges, which can be interpreted as an estimate of the underlying error paths.

In research, one often needs to modify step 2, the weight model, to reflect more complex noise (non-i.i.d., biased, spatially correlated, etc.). In el-loom, this is typically implemented by customizing an EdgeWeigher or related callbacks.

3.3 Negative Log-Probabilities and the “Statistical Physics” View

If we define edge weights as \[ w_e = -\log \Pr(e \text{ occurs}), \] then the weight of an error configuration \(E\) is \[ W(E) = \sum_{e \in E} w_e \] (ignoring constant terms). Maximum likelihood decoding is then \[ E^\star = \arg\min_{E \sim \mathbf{s}} W(E). \] This resembles a ground-state problem under an “energy function” \(W(E)\), which is closely related to Ising-type systems and free-energy minimization in statistical physics. This viewpoint is useful for understanding thresholds and phase transitions, and it naturally connects to el-loom’s Monte Carlo simulations and error sampling.

4. Optimal Bayesian Decoding and Belief Propagation

4.1 From ML to MAP: Marginalizing Logical Probabilities

Fully optimal logical MAP decoding requires computing \[ \Pr([E_\alpha] \mid \mathbf{s}) \propto \sum_{E \in [E_\alpha] \cap \mathcal{E}(\mathbf{s})} \Pr(E). \] Under an i.i.d. Pauli model, \[ \Pr(E) = \prod_{j=1}^n \Pr(E_j), \] but the syndrome consistency conditions \(\mathbf{s}(E) = \mathbf{s}\) impose “parity constraints” among Pauli errors, turning the marginalization into an NP-hard counting problem (#P-hard). This is analogous to the case of classical LDPC codes under belief propagation decoding.

Belief propagation (BP) or message-passing algorithms aim to approximately compute these marginals on a factor graph: \[ \Pr(E_j \mid \mathbf{s}), \] and then infer approximate posteriors for the logical error. For quantum LDPC and CSS codes, it is common to split the problem into X/Z subproblems, corresponding to BP decoding on two classical codes.

4.2 Factor-Graph Formulation of BP and Update Equations

For a classical binary parity-check code, the message update equations on the factor graph are:

  • Message from variable node \(v\) to check node \(c\): \[ m_{v \to c}(x_v) \propto \Pr(x_v) \prod_{c' \in N(v) \setminus \{c\}} m_{c' \to v}(x_v), \] where \(x_v \in \{0,1\}\) is the error bit, and \(\Pr(x_v)\) is the prior.
  • Message from check node \(c\) to variable node \(v\): \[ m_{c \to v}(x_v) \propto \sum_{\{x_{v'}\}_{v' \in N(c) \setminus \{v\}}} \mathbb{1}\Big[ \sum_{v' \in N(c)} x_{v'} \equiv s_c \pmod 2 \Big] \prod_{v' \in N(c) \setminus \{v\}} m_{v' \to c}(x_{v'}), \] where \(s_c\) is the syndrome bit.

The final approximate marginal is \[ \hat{\Pr}(x_v) \propto \Pr(x_v)\prod_{c \in N(v)} m_{c \to v}(x_v). \] For a quantum CSS code, one can run BP separately on the X- and Z-subproblems. For non-CSS codes, one may use generalized BP or a Pauli-group generalization.

In el-loom, you can construct a factor graph from the code’s parity-check matrix or stabilizer structure, and then implement a BPDecoder class that adheres to the Decoder interface: 


class BPDecoder(Decoder):
    def __init__(self, task, max_iters=50, damping=0.5):
        self.task = task
        self.max_iters = max_iters
        self.damping = damping
        self.graph = build_factor_graph(task.code)

    def decode(self, syndrome):
        beliefs = run_bp(self.graph, syndrome,
                         max_iters=self.max_iters,
                         damping=self.damping)
        return self._beliefs_to_recovery(beliefs)

Here, build_factor_graph and run_bp can be developed as fully independent components and reused across different codes and noise models.

5. Machine-Learning-Based Decoding: From Statistical Models to Learned Models

5.1 Statistical Meaning: From Hand-Crafted Probability Models to Learned Posteriors

Earlier we assumed particular factorizations and noise-model forms for MWPM and BP; the edge weights and message updates are explicitly derived. Alternatively, if we have sufficient simulated or experimental data \((\mathbf{s}^{(i)}, L^{(i)})\), we can attempt to use machine learning to directly approximate the mapping \[ f_\theta: \mathbf{s} \mapsto \hat{L}, \] or better still, approximate the posterior distribution \[ q_\theta(L \mid \mathbf{s}) \approx \Pr(L \mid \mathbf{s}). \] This is essentially a supervised classification or probabilistic prediction problem.

For stabilizer codes, the syndrome dimension can be very large (especially in space-time decoding), so it is common to use CNNs, GNNs, or transformers to capture both local and long-range structure in the syndrome patterns. Quantum decoding has specific challenges: the input space is huge, labels can be noisy, there may be distribution shifts (mismatch between experiments and simulations), and we need accurate estimation of extremely low error-rate tails.

5.2 Integrating ML Decoders into el-loom

el-loom is not an ML framework, but it can conveniently serve as a data generator and evaluation platform. The basic workflow is:

  1. Use a DecodingTask to generate a large number of samples \((\mathbf{s}, L)\).
  2. Train a neural network using an external ML framework (PyTorch, JAX, TensorFlow, etc.).
  3. Wrap the trained model as a Decoder subclass.
  4. Use el-loom’s sampling/experiment API to evaluate the decoder’s performance.

Example of data generation:

6. Multi-Round Measurements and Space-Time Decoding

6.1 Syndrome History as a Three-Dimensional Graphical Structure

On actual quantum hardware, stabilizer measurements are themselves noisy, and multi-round syndrome measurements are typically employed. Each round’s syndrome \( \mathbf{s}_t \) (\(t = 1,\dots,T\)) can be viewed as a 2D lattice on a time slice. Errors can occur on:

  • Data qubits: causing syndromes to remain flipped over time.
  • Measurement qubits / readout: causing syndromes to flip once in time (a transient flip).

As a result, a single error no longer affects only the syndrome in one round; instead, it induces adjacency relations along the time dimension. This can be embedded in a 3D lattice (2D space + 1D time), where one can apply 3D matching or other 3D decoders.

6.2 Multi-Round DecodingTasks in el-loom

In el-loom, multi-round decoding is typically controlled by a parameter such as n_rounds: 


task = tasks.DecodingTask(
    code=code,
    noise_model=channel,
    n_rounds=T,          # multiple syndrome rounds
    phenomenological=True  # may also mean adding errors directly on the syndrome
)

In this case, the decoder’s input is the syndrome history: \[ \mathbf{S} = (\mathbf{s}_1, \mathbf{s}_2, \dots, \mathbf{s}_T), \] and it should produce a recovery corresponding to a 3D lattice (usually projected to the final round or over the whole time axis).

The MWPM decoder extends the graph structure as follows:

  • Vertices: space-time defects (i.e., time-difference flips of syndrome bits).
  • Edges: spatial edges (space errors), temporal edges (measurement errors), and space-time mixed segments.
  • Edge weights: the negative log-probabilities of the corresponding error events, derived from the noise model.

In the el-loom API, you can usually specify whether the decoder is “time-aware” and whether the noise model includes measurement errors, in order to invoke the appropriate space-time decoder.

7. Implementing Custom Decoders in el-loom: Examples and Mathematical Considerations

7.1 An Example of a Custom ML-Inspired Heuristic Decoder

Suppose we want to build a simple heuristic decoder that combines local syndrome patterns with prior noise bias. For example, if Z-errors occur with much higher probability than X-errors (biased noise), then logical Z-flip probabilities increase and we may want to prioritize correcting Z-related syndromes.

Mathematically, if the noise model is biased Pauli: \[ \Pr(E_j = Z) = p_Z,\quad \Pr(E_j = X) = p_X,\quad \Pr(E_j = Y) = p_Y, \] with \(p_Z \gg p_X, p_Y\). Under an approximate independence assumption, given a syndrome, the posterior odds between single-edge errors become: \(j\) divided by \(\ell_X\) of bold s semicolon \(j\).-->\[ \frac{\Pr(Z_j \mid \mathbf{s})}{\Pr(X_j \mid \mathbf{s})} \approx \frac{p_Z}{p_X} \cdot \frac{\ell_Z(\mathbf{s}; j)}{\ell_X(\mathbf{s}; j)}, \] where \(\ell_Z, \ell_X\) describe how well each error type explains the local syndrome pattern (likelihood). If we design a local scoring function \(f(\mathbf{s}_\text{local})\) to estimate \(\ell_Z / \ell_X\), we can heuristically decide whether to apply Z-recovery or X-recovery on qubit \(j\).

In el-loom, this can be implemented as: 


class BiasedHeuristicDecoder(Decoder):
    def __init__(self, task, pZ, pX, window_radius=1):
        self.task = task
        self.pZ = pZ
        self.pX = pX
        self.window_radius = window_radius
        self.neighborhoods = precompute_neighborhoods(task.code, window_radius)

    def score_Z_vs_X(self, local_syndrome):
        # This could be a hand-crafted rule or a small ML model
        # For example, a logistic score based on the number and shape of nearby syndrome flips
        return some_function(local_syndrome)

    def decode(self, syndrome):
        recovery = identity_pauli(self.task.code.n_qubits)
        for q in range(self.task.code.n_qubits):
            local_s = extract_local_syndrome(syndrome, self.neighborhoods[q])
            log_odds = (
                math.log(self.pZ / self.pX)
                + self.score_Z_vs_X(local_s)
            )
            if log_odds > 0:
                recovery = apply_Z(recovery, q)
            else:
                # maybe no correction or X-correction, depending on design
                pass
        return recovery

Such a decoder is not strictly optimal, but it can be directly compared against MWPM, BP, or neural-network decoders within the el-loom framework.

7.2 Consistent Design across Multiple Codes and Noise Models

A key advantage of el-loom is that the same DecodingTask / Decoder abstractions apply to many different codes (surface, color, quantum LDPC, etc.) and noise models (i.i.d., biased, correlated, circuit-level). Thus, when designing custom decoders, we recommend the following principles:

  • Decouple from specific code structure: encapsulate code-specific information during construction (e.g., via precompute_neighborhoods), rather than hard-coding indices in the decode function.
  • Decouple from the noise model: if the decoder needs additional noise parameters, pass them via the constructor (e.g., pZ, pX, correlations) instead of reading them directly from an internal noise object.
  • Decouple from sampling/experiments: the decoder should only care about input syndromes and output decisions, not about how experiments estimate error rates.

With this design, we have \[ \text{Decoder}: (\text{syndrome space}, \text{hyperparameters}) \to \text{decision space}, \] which can be reused across arbitrary DecodingTasks, maximizing fairness and reproducibility in experimental comparisons.

8. Evaluating Decoder Performance: Logical Error Rate, Threshold, and Confidence Intervals

8.1 Definition and Estimation of Logical Error Rate

Given a code distance \(d\), physical error rate \(p\), and decoder \(D\), we are typically interested in the logical error rate \[ P_L(d, p; D) = \Pr(\text{logical failure} \mid d, p, D). \] A logical failure event can be defined as: “The combination of the recovery and the original error corresponds to a nontrivial logical operation.” Formally, let \[ E: \text{actual error},\quad R = D(\mathbf{s}(E)), \] and if there exist a logical operator \(\bar{L}\neq I\) and a stabilizer \(S\in \mathcal{S}\) such that \[ RE = \bar{L} S, \] we count it as a logical failure.

To estimate this via Monte Carlo: repeat the experiment independently \(N\) times, with \(K\) failures: \[ \hat{P}_L = \frac{K}{N}. \] Since each experiment is a Bernoulli trial, the binomial distribution yields an error estimate. A common approximate 95% confidence interval is \[ \hat{P}_L \pm 1.96 \sqrt{\frac{\hat{P}_L(1-\hat{P}_L)}{N}}. \] For very small error rates (e.g. \(10^{-6}\)), more refined intervals such as the Clopper–Pearson interval are required.

8.2 Sampling and Statistical Analysis in el-loom

el-loom provides experiment/sampling tools that can automatically:

  • Run a large number of trials for given \(p\) and \(d\),
  • Record logical success/failure events,
  • Compute estimates and error bars.

Example code:


from loom import experiments

exp = experiments.DecodingExperiment(
    task=task,
    decoder=decoder,
    n_shots=10_000

result = exp.run()

print("logical_error_rate =", result.logical_error_rate)
print("confidence_interval =", result.confidence_interval)

Internally, DecodingExperiment roughly performs:

  1. Call task.sample() to generate an error + syndrome.
  2. Call decoder.decode(syndrome) to produce a recovery.
  3. Call task.logical_effect(error, recovery) to determine whether a logical failure occurred.
  4. Count the number of failures, and then compute the estimator and confidence interval.

8.3 Threshold Fitting and Finite-Size Scaling

In threshold studies, we are usually interested in the threshold \(p_{\text{th}}\) of a decoder \(D\), such that:

  • When \(p < p_{\text{th}}\), the logical error rate decreases (roughly exponentially) with increasing distance \(d\).
  • When \(p > p_{\text{th}}\), it instead increases or does not improve with larger \(d\).

Theoretically, in the neighborhood of the threshold, finite-size scaling can be expressed as \[ P_L(d, p) \approx F\big((p - p_{\text{th}}) d^{1/\nu}\big), \] where \(F\) is a scaling function and \(\nu\) is a critical exponent. The fitting procedure typically:

  1. Collects \(P_L\) data for multiple \(d\) and \(p\) values.
  2. Assumes a parametric form, such as \[ \log P_L \approx A + B (p - p_{\text{th}}) d^{1/\nu}, \] or extensions thereof.
  3. Uses least squares or Bayesian inference to fit \((p_{\text{th}}, \nu, A, B,\dots)\).

In el-loom, you can apply Python’s numpy/scipy or Bayesian toolkits (such as pymc) to the outputs of DecodingExperiment to perform post-processing and threshold fitting. The key point is that el-loom handles data generation and bookkeeping, allowing you to concentrate on the statistical analysis itself.

9. Comprehensive Example: From Modeling to Decoder Comparison

We conclude with a comprehensive example that summarizes the full pipeline from modeling and decoding to statistical evaluation: comparing three decoders (MWPM, BP, Neural) for a surface code under biased noise.

9.1 Building the Code and Noise Model


from loom import codes, noise, tasks, decoders, experiments

d_list = [5, 7, 9]
p_list = [0.01, 0.03, 0.05, 0.07]

results = []

for d in d_list:
    code = codes.PlanarSurfaceCode(distance=d)

    # Biased noise, e.g., pZ much larger than pX, pY
    channel = noise.BiasedPauliNoise(
        pX=0.001, pY=0.001, pZ=0.01
    )

    task = tasks.DecodingTask(
        code=code,
        noise_model=channel,
        n_rounds=1
    )

    # Three decoders:
    mwpm_dec = decoders.MWPMDecoder(task)
    bp_dec   = MyBPDecoder(task)
    nn_dec   = NeuralDecoder(task, pretrained_model)

    for p in p_list:
        # Here we assume the noise model can dynamically update the physical error rate
        channel.set_error_rate(p)

        for dec_name, dec in [
            ("mwpm", mwpm_dec),
            ("bp", bp_dec),
            ("nn", nn_dec),
        ]:
            exp = experiments.DecodingExperiment(
                task=task,
                decoder=dec,
                n_shots=20_000
            )
            res = exp.run()
            results.append({
                "d": d,
                "p": p,
                "decoder": dec_name,
                "logical_error_rate": res.logical_error_rate,
                "ci": res.confidence_interval,
            })

Next, you can use pandas and matplotlib to plot and compare results, for example, plotting \(P_L\) vs \(p\) for each \(d\), with different colors for the three decoders. You may also use log-log plots to examine error-suppression behavior.

9.2 Interpretation from the Perspective of Statistical Inference

If, under biased noise, the neural decoder’s curves clearly outperform those of MWPM, this indicates that it has, in some sense, produced a more accurate estimate of the posterior \[ \Pr(L \mid \mathbf{s}) \] or \(\Pr(E \mid \mathbf{s})\). This reflects:

  • The factorization assumptions underlying MWPM (independence, shortest path ≈ highest probability) become seriously invalid in biased or correlated regimes.
  • The ML-based model learns decision boundaries in the high-dimensional syndrome space that more closely approximate the true posteriors.

The BP decoder may perform in between the two in moderately biased regimes, as it partially accounts for parity constraints and prior bias but is still limited by loops and factorization assumptions.

This illustrates that decoder design = statistical assumptions about noise and syndrome structure + computationally feasible trade-offs. el-loom enables us to quantify and compare the effects of different statistical assumptions under clearly specified experimental settings, providing data-driven support for further theoretical analysis.

10. Conclusion: Using el-loom as a Platform Linking Theory and Implementation

Starting from rigorous mathematical definitions, this lesson has treated the decoding problem in quantum error correction as a statistical inference task, and discussed:

  • The theoretical formulation of Bayesian posteriors and logical MAP decoding.
  • The graph-theoretic and energy-based viewpoints of MWPM decoding under i.i.d. Pauli noise.
  • The application of belief propagation and factor graphs to quantum LDPC/CSS codes.
  • How machine-learning-based decoders approximate posterior distributions and how to implement them in el-loom.
  • The 3D structure of space-time decoding under multi-round measurements.
  • How to implement custom decoders in el-loom and carry out fair, statistically significant performance evaluations.

At the PhD and research level, el-loom serves as a reproducible experimentation and inference platform: you can precisely define a code + noise + decoding task, plug in your own decoding algorithms, and use systematic sampling and statistical analysis to verify their behavior in various regimes (biased, correlated, circuit-level, multi-round), while rigorously comparing them with existing decoders (MWPM, BP, ML-based).

For further exploration, you may:

  • Develop specialized MWPM or BP decoders for non-planar codes (such as color codes or hypergraph product codes).
  • Design decoders that explicitly exploit correlation structures under correlated noise, and compare them with standard decoders that assume i.i.d. noise.
  • Incorporate Bayesian hierarchical models (e.g., with uncertain noise parameters) into the decoding process, and update decoding strategies via online learning.

In these advanced directions, el-loom provides a stable “experimental floor,” allowing you to tightly integrate theoretical derivations, algorithm design, and real data analysis, thereby advancing quantum error-correction decoding research towards a more mature and experimentally verifiable stage.
